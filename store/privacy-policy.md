# Privacy policy

## Search Tabs for Zammad

Effective date: 28 October 2026. Publisher: Eugene Bachura. Contact: [eugene.bachura@gmail.com](mailto:eugene.bachura@gmail.com).

This independent browser extension keeps multiple search queries as tabs in the classic Zammad interface and helps users compose search filters.

## Information handled

On sites that you explicitly enable, the extension reads the current search query, Zammad account ID, interface language and state, priority and group labels needed by its filter builder. It also handles custom search-tab names you enter and task identifiers used to restore tab positions. Queries and tab names can contain names, email addresses, ticket references, or other personal and confidential information that you enter.

The extension reads the existing page's task navigation and native dialog markup to display its controls. It does not read ticket conversations or attachments to build these controls. Search results continue to be provided by your Zammad installation.

## Storage and purpose

In regular windows, search text, custom tab names and tab positions are stored in the browser's local extension storage on your device. Entries are grouped by Zammad origin, application path and account ID so searches can be restored and separated between accounts. The list of sites enabled in regular windows and the preference for sharing private searches are also stored locally. Site access grants are managed by the browser. Filter choices and unfinished drafts are held in memory while the page is open.

Pending activation requests can be stored locally with the site address, browser tab ID and request time so enabling can finish if the browser's permission prompt closes the toolbar panel. Requests older than five minutes are ignored. Pending requests are removed when handled or canceled, or when saved extension data is cleared.

Data is used only to provide search tabs and the filter builder. The extension's use of information complies with the Chrome Web Store User Data Policy, including its Limited Use requirements.

## Private windows

Private windows require your permission in the browser's extension settings. You must also enable the Zammad site for each private session. By default, private queries, tab names and tab positions are stored in memory using session storage, separately from regular windows. They are removed when the last private window closes, when the browser restarts, or when the extension is reloaded, updated or disabled.

If you turn on "Use shared saved searches in private windows" in Settings, private windows use the regular profile's saved searches for the same Zammad origin, application path and account ID. Queries, names and positions created or changed in this mode are stored in local extension storage and remain after private windows close. Turning this option off does not remove data already saved in the regular profile. Existing temporary searches are kept separately in memory until the private session ends; changing the option does not copy that saved set into local storage. The current query on an open Zammad page is recorded in the selected mode when the integration restarts.

Sites enabled in private windows and their pending activation requests are always kept in memory for the private session, including the site address, browser tab ID and request time. Requests expire after five minutes. These records and all temporary private searches are removed after the last private window closes or when you clear extension data. Sharing saved searches does not share your Zammad sign-in or authentication cookies.

## Sharing and network activity

The extension does not send data to the publisher or third parties. It has no analytics, advertising, tracking, remote code, cloud backup or browser storage synchronization. The publisher cannot access your saved queries.

Running a search uses the Zammad page you already opened. That page communicates with your chosen Zammad server under its own privacy and security rules. The extension also reuses that page's native styles and icons. The extension does not create an additional destination for your queries.

## Retention and removal

Searches saved in local extension storage, including their custom names and positions, remain in your browser profile until you close their search tabs, remove saved data through the extension's settings, or uninstall the extension. Temporary private searches follow the retention rules above. Signing out hides your searches but does not erase them. Revoking site access through the browser prevents further page access and does not itself erase previously saved queries.

Choose "Disable on this site" in the toolbar panel to stop the integration on that site while keeping its saved queries. To remove all saved queries, open Settings and choose "Disable all sites and remove saved searches". The extension disables its integration and asks the browser to revoke optional site access. If the browser cannot remove that access, the panel explains how to remove it in browser settings; the integration remains disabled. These actions do not delete tickets or other information held by your Zammad server.

## Security

Saved queries are local browser-profile data, not an encrypted vault. People or software with access to your browser profile or device may be able to read them. The extension does not request passwords, authentication cookies, payment details or browser history.
